# video-downloader-by-browser 使用指南

> 名称：`video-downloader-by-browser`｜版本：1.1.2
> 一句话：**手动介入式分片视频下载**——用有头浏览器（用户可见、不自动关闭）打开视频页，拦截真实流地址并高速并行下载分片（TS 流 / m3u8 / 大分片 MP4），无损合并为完整 MP4，经用户验收再清理分片。
> 适用：需要分片下载的流媒体视频，尤其是需要登录 / 短信验证码 / 滑动验证 / 观看密码 / 切换清晰度才能播放的受限站点（优酷、腾讯视频、爱奇艺、B 站等）。

## 一、核心理念

**能自动的自动，不能自动的立刻停下交给用户。**

这类站点的反爬手段（登录、短信验证码、滑动验证、会员画质）本质就是拦自动化。与其对抗，不如：用**有头浏览器**把界面完整呈现给用户，用户手动完成人机验证，我们只负责在旁边**监听网络请求把流地址抓下来**，然后甩开浏览器用**并行 HTTP** 高速下载。

**两条铁律：**

1. 用户必须能看到浏览器窗口，脚本**绝不能自动关闭窗口/浏览器**
2. 合并完成**必须经用户验收通过后**才能删除中间分片，绝不提前删

## 二、适用判断

| 场景 | 是否用本 Skill |
|---|---|
| TS 流 / m3u8 / 大分片 MP4 等分片视频，需要拦截真实流地址下载 | ✅ 正是本 Skill 的目标 |
| 分片视频需要登录 / 验证码 / 滑动验证才能播放 | ✅ 手动介入协议处理 |
| 需要会员才能看高画质 / 需要观看密码 | ✅ |
| yt-dlp、you-get 等现成工具已直接支持的站点 | ❌ 用现成工具更省事 |

## 四、标准流程（6 阶段）

1. **环境准备**：新电脑先跑 `bash scripts/setup.sh`（幂等，自动装 playwright-core、检测 Chrome / ffmpeg、语法自检）
2. **拉起常驻浏览器**：`node scripts/browser_ctl.mjs <工作目录> "<视频页URL>" <正片最小时长>`（固定本机 Chrome + 全局共享 profile，登录一次处处免登录）
3. **判断页面状态**：看 `browser.log` 的登录态与拦截结论，需要登录 / 滑动验证时停下交给用户；优酷观看密码可 `echo "pwauto <密码>" > cmd.txt` 全自动过
4. **采集分片 URL**：`python scripts/youku_collect.py <工作目录> [总时长]`（seek 各分片起点，监听器记录 URL）
5. **探测 + 并行下载**：`youku_probe.py`（窗口 URL → 整分片 URL）→ `youku_download.py`（单分片 6 路 Range × 多分片并发，实测 2.45 GB / 175 秒）
6. **合并 + 校验 + 验收 + 清理**：`merge_verify.py`（无损合并 + 拼接点解码体检）→ 用户验收 → `cleanup.py`（带安全闸，默认进废纸篓）

详细操作手册、手动介入协议、踩坑清单见 [SKILL.md](SKILL.md)。

## 五、依赖

- Node.js 18+ 与 `playwright-core`
- 本机 Google Chrome（有头模式固定用它）
- Python 3.8+（下载/合并脚本全部只用标准库，零 pip 依赖）
- ffmpeg 与 curl

## 六、安装

```bash
clawhub install video-downloader-by-browser
```

或解压 / clone 后把 `video-downloader-by-browser` 文件夹放入 skills 目录，首次使用前运行 `bash scripts/setup.sh`。

## 七、安全说明

- 任何账号密码、短信验证码、人机验证都由用户在浏览器里手动完成，本工具**不存储任何凭证**
- 下载内容请确保你有权保存；请尊重版权与各平台服务条款
- 中间分片默认不物理删除（进废纸篓 / 重命名），验收通过前可随时恢复
